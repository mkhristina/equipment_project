# Архитектура проекта Equipment Maintenance

## 1. Общее описание

Проект предназначен для управления оборудованием и заявками на его техническое обслуживание.

Система состоит из нескольких компонентов, которые выполняют отдельные задачи и взаимодействуют друг с другом.

## 2. Основные компоненты

### Django

Django используется как основное веб-приложение проекта.

Основные функции:
- управление оборудованием;
- управление заявками на обслуживание;
- административная панель;
- REST API на основе Django REST Framework;
- сбор статистики.

### FastAPI

FastAPI предоставляет отдельный API для работы с заявками на обслуживание.

Основные функции:
- создание заявок;
- получение списка заявок;
- получение заявки по идентификатору;
- проверка входящих данных с помощью Pydantic.

### MongoDB

MongoDB используется для хранения журнала аудита.

В журнал записываются события создания и изменения оборудования и заявок.

### RabbitMQ

RabbitMQ используется как брокер сообщений.

При создании заявки через FastAPI формируется событие, которое отправляется в очередь `maintenance_requests`.

### Consumer

Consumer получает сообщения из RabbitMQ, обрабатывает их и подтверждает получение.

## 3. Взаимодействие компонентов

1. Пользователь отправляет запрос на создание заявки через FastAPI.
2. FastAPI проверяет данные с помощью Pydantic.
3. Заявка создаётся во временном хранилище приложения.
4. FastAPI отправляет событие в RabbitMQ.
5. RabbitMQ помещает сообщение в очередь `maintenance_requests`.
6. Consumer получает сообщение и обрабатывает его.

Django отдельно управляет оборудованием и заявками через собственный REST API.

## 6. Важное замечание

FastAPI на текущем этапе использует временное хранилище заявок в оперативной памяти. После перезапуска приложения созданные через FastAPI заявки теряются.

RabbitMQ используется для передачи событий о создании заявок, а MongoDB — для журнала аудита Django.
