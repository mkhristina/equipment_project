# Equipment Management System

Система учёта оборудования и управления заявками на техническое обслуживание.

## 1. О проекте

**Equipment Management System** — учебный проект на Python, предназначенный для хранения информации об оборудовании, создания заявок на техническое обслуживание и обработки событий.

Система позволяет:
- хранить сведения об оборудовании;
- создавать и просматривать заявки на обслуживание;
- отслеживать состояние оборудования и приоритет заявок;
- работать с данными через REST API;
- сохранять события аудита в MongoDB;
- передавать события через RabbitMQ;
- запускать сервисы в Docker-контейнерах.

В проекте используются Django, FastAPI, SQLite, MongoDB и RabbitMQ.

## 2. Что необходимо установить перед запуском

Для самого простого запуска рекомендуется использовать Docker.

Перед началом работы установите:

1. **Docker Desktop** — программа для запуска контейнеров.
   Скачать: https://www.docker.com/products/docker-desktop/

2. **Git** — программа для скачивания проекта с GitHub.
   Скачать: https://git-scm.com/downloads

3. **Visual Studio Code** — редактор кода. Он необязателен для запуска, но удобен для просмотра проекта.
   Скачать: https://code.visualstudio.com/

### Проверка установки

После установки откройте PowerShell.

PowerShell можно найти через меню «Пуск» Windows.

Введите по очереди следующие команды:

Проверка Git:

```powershell
git --version
```

Проверка Docker:

```powershell
docker --version
```

Проверка Docker Compose:

```powershell
docker compose version
```

Если команды выводят номера версий, необходимые программы установлены.

Также запустите Docker Desktop и дождитесь, пока он полностью загрузится.

## 3. Как скачать проект

### Шаг 1. Откройте PowerShell

Перейдите в папку, в которой хотите хранить проект.

Например, чтобы сохранить его на рабочем столе, выполните:

```powershell
cd "$HOME\Desktop"
```

Выполните команду:


## 4. Запуск всей системы через Docker Compose

Это основной и рекомендуемый способ запуска проекта.

Docker Compose автоматически создаёт и запускает необходимые контейнеры.

### Шаг 1. Соберите и запустите сервисы

В PowerShell, находясь в папке `equipment_project`, выполните:

```powershell
docker compose up --build -d
```

Что делает команда:
- `docker compose` — запускает управление сервисами проекта;
- `up` — создаёт и запускает контейнеры;
- `--build` — собирает образы приложений;
- `-d` — запускает контейнеры в фоновом режиме.

При первом запуске сборка может занять несколько минут. Дождитесь завершения команды.

### Шаг 2. Проверьте, что контейнеры запущены

Выполните:

```powershell
docker compose ps
```

В списке должны отображаться сервисы проекта:

- Django;
- FastAPI;
- MongoDB;
- RabbitMQ;
- Consumer.

У запущенных контейнеров статус должен быть `Up` или соответствующий статус готовности.

### Шаг 3. Откройте сервисы в браузере

После запуска откройте нужный адрес.

| Сервис | Адрес |
|---|---|
| Django REST API | http://localhost:8002/api/ |
| Django Admin | http://localhost:8002/admin/ |
| Django Statistics | http://localhost:8002/statistics/ |
| FastAPI | http://localhost:8001/ |
| FastAPI Swagger | http://localhost:8001/docs |
| FastAPI Health | http://localhost:8001/health |
| RabbitMQ Management | http://localhost:15673/ |

**Как проверить FastAPI:**

Откройте http://localhost:8001/health

Если сервис работает, он вернёт ответ с информацией о состоянии приложения.

**Как проверить документацию API:**

Откройте http://localhost:8001/docs

Появится интерактивная документация Swagger, в которой можно просматривать маршруты и отправлять тестовые запросы.

### Шаг 4. Вход в Django Admin

Откройте:

http://localhost:8002/admin/

Для входа нужны имя пользователя и пароль администратора Django.

Если администратора ещё нет, создайте его из PowerShell:

```powershell
docker exec -it equipment-django-compose python manage.py createsuperuser
```

Далее следуйте инструкциям в терминале: укажите имя пользователя, электронную почту (если потребуется) и пароль.

После создания администратора вернитесь в браузер и войдите в панель управления.

### Шаг 5. Вход в RabbitMQ Management

Откройте:

http://localhost:15673/

Используйте следующие учётные данные:

- Логин: `equipment_user`
- Пароль: `equipment_pass_2026`

В панели можно просматривать состояние RabbitMQ и очереди сообщений.

## 5. Как остановить проект

Чтобы остановить контейнеры, откройте PowerShell в папке проекта и выполните:

```powershell
docker compose down
```

Команда остановит и удалит контейнеры, созданные Docker Compose. Именованные тома с данными при этом сохраняются.

Чтобы снова запустить проект, выполните:

```powershell
docker compose up -d
```

Если нужно повторно собрать образы после изменения кода, используйте:

```powershell
docker compose up --build -d
```

**Важно:** не добавляйте параметр `-v` к команде `docker compose down`, если хотите сохранить данные в томах.

## 6. Локальный запуск Django без Docker

Этот способ подходит для разработки и запуска Django отдельно от остальных сервисов.

Для него потребуется установленный Python.

### Шаг 1. Создайте виртуальное окружение

Находясь в корневой папке проекта, выполните:

```powershell
python -m venv .venv
```

Виртуальное окружение создаёт отдельную среду для установки библиотек проекта.

### Шаг 2. Активируйте виртуальное окружение

```powershell
.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает выполнение скрипта активации, можно использовать команду:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

После этого повторите команду активации.

### Шаг 3. Установите зависимости

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### Шаг 4. Примените миграции

```powershell
python manage.py migrate
```

### Шаг 5. Создайте администратора

```powershell
python manage.py createsuperuser
```

Введите данные для входа в административную панель.

### Шаг 6. Запустите Django

```powershell
python manage.py runserver
```

После запуска Django будет доступен по адресу:

http://127.0.0.1:8000/

Дополнительные страницы:

- Административная панель: http://127.0.0.1:8000/admin/
- Статистика: http://127.0.0.1:8000/statistics/
- REST API: http://127.0.0.1:8000/api/

Чтобы остановить сервер, нажмите `Ctrl + C` в терминале.

**Примечание:** локальный запуск Django сам по себе не запускает MongoDB и RabbitMQ. Для работы интеграций с этими сервисами они должны быть отдельно запущены и правильно настроены.

## 7. Основные возможности системы

### Управление оборудованием

В системе можно:
- добавлять оборудование;
- просматривать сведения об оборудовании;
- редактировать информацию;
- отслеживать текущее состояние;
- использовать инвентарные номера для идентификации оборудования.

### Управление заявками

Для каждой заявки хранятся:
- оборудование, к которому относится заявка;
- описание неисправности или необходимых работ;
- приоритет;
- статус;
- дата создания.

Одно оборудование может иметь несколько заявок.

### Django Admin

Административная панель позволяет управлять двумя основными моделями:

- `Equipment` — оборудование;
- `MaintenanceRequest` — заявки на техническое обслуживание.

Настроены отображение полей, фильтрация и поиск записей.

## 8. Django REST API

Django REST Framework предоставляет API для работы с оборудованием и заявками.

Основной адрес:

http://localhost:8002/api/

API позволяет получать и обрабатывать данные приложения через HTTP-запросы.

## 9. FastAPI

FastAPI — отдельный сервис для работы с заявками на техническое обслуживание.

Основные маршруты:

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/health` | Проверка состояния сервиса |
| GET | `/requests` | Получение списка заявок |
| GET | `/requests/{request_id}` | Получение заявки по ID |
| POST | `/requests` | Создание новой заявки |

Документация Swagger:

http://localhost:8001/docs

Для проверки и валидации входящих данных используется Pydantic.

## 10. MongoDB и аудит

MongoDB используется для хранения событий аудита.

При сохранении или изменении данных оборудования и заявок Django может формировать события, которые записываются в коллекцию `audit_events` базы данных `maintenance_audit`.

Для подключения используется переменная окружения `MONGO_URI`.

При запуске через Docker Compose Django обращается к MongoDB по внутреннему адресу Docker-сети.

## 11. RabbitMQ и обработка сообщений

RabbitMQ используется для передачи событий о создании заявок на техническое обслуживание.

В проекте предусмотрена следующая последовательность:

1. Клиент отправляет запрос на создание заявки в FastAPI.
2. FastAPI проверяет входящие данные.
3. Сервис отправляет событие в очередь `maintenance_requests`.
4. Consumer получает сообщение из очереди.
5. Consumer обрабатывает сообщение и подтверждает его получение.

Для взаимодействия с RabbitMQ используется библиотека `pika`.

## 12. Статистика

В Django реализована страница статистики:

http://localhost:8002/statistics/

Она возвращает данные в формате JSON:

- `equipment_total` — общее количество единиц оборудования;
- `equipment_in_repair` — количество оборудования в ремонте;
- `critical_open_requests` — количество открытых заявок с критическим приоритетом.

## 13. Тестирование

Для запуска автоматических тестов используется `pytest`.

Если виртуальное окружение ещё не активировано, сначала активируйте его:

```powershell
.venv\Scripts\Activate.ps1
```

Установите зависимости, если они ещё не установлены:

```powershell
pip install -r requirements.txt
```

Запустите тесты:

```powershell
pytest
```

После выполнения pytest покажет результаты тестирования и информацию о пройденных или не пройденных тестах.

## 14. GitHub Actions

В проекте настроена автоматическая проверка тестов с помощью GitHub Actions.

Файл настройки:

`.github/workflows/tests.yml`

При отправке изменений в ветку `main` или создании Pull Request автоматически выполняются:

1. Получение исходного кода.
2. Установка Python 3.13.
3. Установка зависимостей.
4. Запуск автоматических тестов.

Результаты проверки можно посмотреть во вкладке **Actions** репозитория GitHub:

https://github.com/mkhristina/equipment_project/actions
